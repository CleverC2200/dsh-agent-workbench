# Page presentation recovery

Workbench owns page choice, the page's interpretation choices and references to Core Sessions. Core owns the actual Session, its current preset, history, conversation drafts and retention. Manage owns installed resource declarations. GEA owns identity and business authorization.

`WorkbenchController` accepts a presentation memory with `getSnapshot` and `set`. The Client uses Core's public `createSnapshotStore`, under `agent-workbench.presentation.v2`. The only accepted format is version 2. It records the selected page, Session addresses and preset/workspace/subject hints, and the existing narrow `validHtmlViewState` projections. It contains no Core binding, Session log, credential, login flag, grant, model response or derived query result. This browser-local memory is not a Session store or cross-device synchronization.

Reconstructing a Controller does not open or create a Session. Recovery waits for Core's directory to be ready, verifies the exact saved member and workspace, and borrows that Session through `retain`/`ready`. The current preset is read from Core's projection. Missing or mismatching addresses are visible failures; the page does not silently create a replacement. Normal navigation then uses `uiWorkspace.openSession`. Every borrowed reference is released.

Business recovery waits for an error-free confirmation from GEA's read-only projection. The stable subject comes from GEA; Workbench does not derive identity from a label or cached login flag. A new Host generation obtains a fresh page owner and grant. No stored owner or grant survives restart. Different subjects do not reuse an old association, and UI intent stays partitioned by subject and Session. Static pages do not gain a GEA login requirement.

Each declared interpretation retains its own Session address. Selecting another interpretation uses normal resource selection and a fresh Session or an existing address whose actual preset/workspace is confirmed. It never changes the preset of a completed conversation to bypass Core's lock. An offered interpretation is a resource hint; installed availability and GEA authorization are still separate checks.

Version 1 presentation data is not decoded at runtime. This change leaves Core's persistent Sessions and user history intact. Any deployment migration of former presentation data is a separate upgrade operation, not a compatibility branch in this controller.

The implementation uses the fixed Core `5badb15009ae1756c3afe0ae0cef1faafc290ccc`: `packages/client/store` for browser snapshots; `packages/api/session-controller` for directory/retain/projection; and `packages/client/ui-workspace` for navigation. The adopted capability is the public browser store, not a new persistence framework. `tests/workbench-recovery.test.mjs` checks reconstruction without Session side effects, interpretation and scope separation, explicit UI intent, and rejection of obsolete or malformed records. Actual browser reload, normal Host restart and business authorization have separate harness receipts.
