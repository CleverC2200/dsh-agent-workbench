# 改单率 BI 数量口径

全国改单率分子、分母及客户下钻仅纳入 pickup_point 为 01（郑州）、02（华东）、03（西南）、04（华南）、37（遂平）的明细。郑州按 pickup_point=01 筛选，不按基地归属替代。

## 统计周期与筛选

数据来源为 agents_scm_execute_detail_d，按 order_close_time（订单关单时间）归属周期，采用起始包含、结束不包含的范围。缺该时间不参与，不以 header_addtime、wms_order_close_time 或物流轨迹 lastshipmenttime 替代，也不关联物流轨迹表。

与 BI 一致，仅保留 detailstatus<>20、is_short_transfer='非短拨'、createsource='20'；剔除 is_virtual 为1/2、timeout_code 为14/16的明细，后两者空值保留。不再按仓库维表重新推断短驳，不附加 is_stat=1 或 orderstatus<>90 条件。三个数量字段全部为空的明细不统计。

## 分子与分母

有效订单量优先取 D 最后修改量 dms_last_update_qty，否则取调整需求量备份 need_qty_origin，均为空时按0，真实0保留。

仅当客户要求改单量 change_order_qty≥0 且小于有效订单量时，明细改单量=有效订单量−客户要求改单量；加货、数量相等、客户要求改单量为空或负值时分子为0。分母为全部保留明细的有效订单量合计，客户要求改单量为空或负值不会单独剔除分母。

改单率=明细改单量合计÷有效订单量合计×100%。不增加锁定期或改单时间条件，不按订单张数、SKU种类数或明细条数计率。

看板汇总、比较期、Agent 独立问数及下钻共用 skuAmendmentEventsSql 和 amendmentReductionSql，口径说明共用 amendmentMetricContract。计算版本为 quantity-order-close-reduction-only-bi-v5；构建时查询与运行时源码摘要共同生成缓存版本，阻止旧快照继续当作当前结果。

## 真实数据核验（2026-11-12）

统计 order_close_time 从2026-11-01（含）至2026-11-12（不含），与提供的 BI 明细核对：全国分子55,678、分母2,747,306，改单率2.0266399156%（展示2.03%）。郑州11,374/1,319,900；华东2,153/160,982；西南11,795/265,262；华南3,451/234,458；遂平26,905/766,704。

同一范围内，看板共享汇总、比较期及 Agent 汇总与明细合计一致，待判定明细为0。业务周期按订单关单时间筛选；本次使用查询时可见的数据，不将数据加载时间作为业务日期，也不声称还原11月11日当时的数据库快照。
