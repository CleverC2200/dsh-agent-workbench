# Agent 插件原版界面恢复

本轮按用户要求收回可见内容：界面以最初迁入的业务插件为准，取数继续使用各 Agent 的新版 `sql.config.json` 和统一 GEA 通道。

## 对照来源

| 插件 | 原版来源 | 恢复的可见内容 |
| --- | --- | --- |
| 分仓库存 | [固定来源](../business/inventory-fc/SOURCE.md) | 5 张主卡片、6 个业务页签；补货表的 37 个原始列名和顺序，货龄、计划、基地资源及运营观察的业务展示。 |
| 全链库存 | [固定来源](../business/inventory-qll/SOURCE.md) | 复用原版主卡片组件；4 个业务页签；按原版结构表展示公司、基地、分仓、渠道库存等业务列，组织结构中的分层入口按需读取。 |
| 经销商库存与定补货 | [固定来源](../business/inventory-dealer/SOURCE.md) | 原版 8 张总览卡片、3 个健康度区域、5 个库存页签和 4 个订单页签；恢复原版业务列顺序和组合单元格。 |
| 基地库存 | [固定来源](../business/inventory-aqkc/SOURCE.md) | 保留原版看板、基地选择与层级展开；去掉卡片覆盖计数、追加来源面板；恢复平均货龄等原始列名。 |
| 产销协同工作台 | [固定来源](../business/inventory-apsplan/SOURCE.md) | 保留原版智能工作台、产销视角及指标分组；移除追加来源工作区、读取成功横幅和卡片中的技术性说明。 |

不再将来源表页签、覆盖行数、源记录数、额外汇总卡片等附加到业务界面。缺失字段继续由[缺失字段清单](agent-missing-fields.md)维护。查询失败仍在原页面显示错误；失败和权限拒绝不伪装成 0。

## 新数据绑定

原始业务列的显示合同集中在 [original-business-views.ts](../business/shared/original-business-views.ts)。合同只决定列名、顺序和组合显示，不修改 SQL、参数、返回权限或源字段目录。列表默认每页 10 行，翻页重新调用已注册的查询。

最大库龄不写入“平均货龄”列。主卡片“当前货龄”使用目前可取得的最大库龄，解释保留在悬停提示中；平均货龄没有等价来源时继续为空。基地未备单数量保留在当前订单卡片的新版绑定中，不将月累计订单数填入分仓当前待发数量。

组织结构将基地、分仓和渠道分别查询和展示。来源日期不同的数据不在浏览器中拼成一个伪造快照。原有箱单位及 `1件=1箱` 的业务确认继续生效。

当前交付为源码与本地预览，不代表已发布或已安装到 GEA 客户端。

## 原版样式与布局复用

后续样式复核将业务列表从通用来源容器中独立出来：[OriginalBusinessList](../business/shared/original-business-list.tsx) 复用原版 DSH 表格、输入框、按钮和分页；全链继续使用原版可视区横向滚动组件，分仓及基地表格沿用各自原始样式。读取、权限错误、分页参数仍由原来的数据组件持有，没有修改 SQL 配置。

经销商和全链恢复原版 Tabs；经销商客户筛选收回原版菜单位置，避免常驻输入框撑高顶部。浅色模式恢复原版辅助文字、分隔线及悬停边框色，深色模式继续跟随客户端。产销协同继续使用原始 `provided-board.css`，仅恢复被主题适配覆盖的浅色辅助文字色。
