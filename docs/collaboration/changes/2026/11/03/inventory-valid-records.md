# 库存首屏读取与有效记录汇总

全链和分仓默认首屏将批次发现与数据读取合并为一次受控请求，精简固定输入条件和重复长别名。返回字段保持独立，权限裁剪、完整分页、同批次校验、身份隔离和显式刷新继续生效；非默认筛选仍执行各自查询。首屏预取只复用短加载窗口，不能将业务行当作长期批次缓存。

按用户本次明确要求，分仓汇总跳过异常或缺失的指标记录，其余有效记录继续计算；真实零值仍有效。展望周转的库存和日均计划采用同一有效分仓/SKU集合，避免只漏掉分母或将无效库存计入。全部未知或日均合计为零时仍显示横线。同步汇总、明细路径、人工试算和模型证据保持此口径；独立指标不会因为某条记录缺计划而丢掉其已知库存。

分仓提示词取消“短正文内列出所有指标”的冲突要求，真实模型用当前页面证据成功生成正文。无洞察内容时页面显示横线，卡片和列表不受模型失败影响。GEA 运行时保持已发布版本，未混入销售计划重提认证切换。

相对上一版的有意行为变化是：部分异常不再让整项可计算汇总变成未知。用户原话为“如果是异常数据，就忽略到那条记录，其它正常的还是要算的”。未知明细仍未知，不能据此提交补货；权限拒绝或结果不完整也不能当作异常业务记录跳过。全链经销商与基地客户订单逻辑未变，目标冲突卡片和列表继续各自原口径。

验证覆盖：当天同步的全部48项对账；真实网关首屏与原查询字段、顺序比较；有效零值、未知、负数和同范围比值；单请求预取、拒权、刷新、分页与异常批次；真实模型正文。具体性能及最终发布信息记录于本次交付回执。没有删除文件或公共接口。发布技能1.2.0为local_draft。

用户后续明确要求“先别发布，后面改完一起发布”。本次只保留本地修改和验证，不推进远端主线、发行包或频道；版本待统一发版时确定。

## 基地与补货确认追加

基地首屏也合并批次与数据读取，保留默认目标版本及库存月份关联。基地7组原查询与合并查询逐字段/顺序一致，最终两次首屏约3.0秒，原路径约4.5秒。

补货确认新增内部读取视图，分页前筛选需补货记录，默认周期直接读取既有汇总字段。零补货及未知建议不再全量拉取；人工修改数量或计划的SKU保留重算与提交前复核来源。自定义周期保留原计算，普通列表/导出不受影响。原486条分页后只显示1条的长沙样例，改为返回1条；最终两次约4.4秒，原复现36.2秒。南宁零补货样例仅返回0计数、无SKU明细。

验证：新增5项实际SQL用例、8种真实数据对账、基地7项对账、76项查询交互及46项配置合同回归；最终范围调整后16项相关回归通过。构建与定向静态检查通过。网关排查期间仍观察到长尾波动，上述时间是最终连续样本，不能当成响应上限承诺。没有新增表/字段或更改同步SQL，没有实际提交DMS订单，仍暂不发布。

## DMS 主数据与空补货追加

确认弹窗在存在正数补货前不再读取 DMS 主数据，0个SKU隐藏暂存编码表单并显示无需补货。手工数量暂时改为0再恢复时，不重复覆盖已核对的人工编码；切换分仓和身份继续取消旧请求。
