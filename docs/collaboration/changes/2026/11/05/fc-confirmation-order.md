# 分仓补货确认顺序与列表一致

补货列表默认按建议补货量倒序显示，确认弹窗为使用已汇总的确认明细，会先按分仓和 SKU 编码读取。之前弹窗直接展示读取顺序，导致列表首行 80 件与弹窗首行 2 件看似不一致，实际属于不同商品。

确认明细读取完成并应用人工计划后，沿用列表的排序再分页，同时展示产品名称。列表和弹窗继续共用按分仓与 SKU 保存的实际补货量，保留手工修改及零值。显式点击表头排序优先于快捷筛选的默认排序；人工计划列表与弹窗复用同一排序函数。

当前成变桃账号经受控网关核对沈阳 A110：两条读取路径各有 36 个 SKU，建议量合计均为 608 件，逐 SKU 数量完全一致；修复后的顺序也完全一致。验证覆盖打开确认、修改数量、关闭再打开、不同宽度、列表筛选及人工计划行为。没有提交 DMS 订单。

仅修改展示排序和商品名称展示，汇总表、同步 SQL、权限配置及补货公式未变。按用户要求暂不发布。
