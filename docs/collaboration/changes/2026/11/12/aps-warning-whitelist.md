# 预警白名单存储与客户端检测调度

预警管理、新增检测点击后立即显示弹窗；读取失败在弹窗内显示并可重试。任务、执行记录、预警事件和观测统一通过 GEA Host 调用 PG-Warning 的通用 SQL 白名单接口 `/ai/sql/execute`；只读受控网关不接收写入，不回退 PostgreSQL 直连或本地业务文件。

检测任务按当前 GEA 身份隔离，既有其他用户和无归属记录保留。保存采用版本检查及逐条条件更新，重复新建使用稳定任务编号；删除保留执行历史。请求失败或部分写入不视为事务成功，重新读取后再操作。

XXL-JOB 的 `gea-warning-executor` 分组负责触发，独立执行器只保存调度交接和回执。GEA Host 通过现有 HTTPS 入口访问，原有 Agent Session 在已登录客户端执行。按用户“按照现在的逻辑吧”，不部署服务器 Agent 运行时；关闭客户端或账号不在线时不伪造检测成功。

本轮替代原本机 PostgreSQL 与本机回调服务，保留检测规则、生命周期、通知和归属逻辑。用户已明确要求 CRUD 均走白名单并部署执行器，因此不再启用旧直连路径。最新主线 MPS、库存、销售预测与客户端更新修复保留。

已验证：26项预警后端及执行器回归、4项弹窗浏览器回归；真实白名单新增、编辑、软删除、历史回读、重复保存和冲突拒绝；HTTPS 身份校验、调度任务创建、重复保存不新增及停用。完整 Agent 检测、正式插件安装和页面验收仍待完成，不能将接口通过记为全部业务通过。
