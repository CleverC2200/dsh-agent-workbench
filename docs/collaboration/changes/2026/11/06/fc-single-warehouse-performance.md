# 分仓首屏合并读取与组合发布验证

选择单个分仓原先无法复用仅面向全部分仓的首屏结果，六个受控查询在并发限额下排队。保留生成 SQL 中的仓库命名参数及列表筛选范围，同批次、同账号、同仓库的默认首屏卡片与列表合并读取。全部分仓预载不能用于单分仓；旧配置缺少仓库参数时保持原查询。自定义筛选、周期和后续分页仍严格校验输入，不改变权限或指标公式。

同一授权账号与同一日汇总的真实网关对照中，两处非空分仓首次取数从10.5秒及9.5秒降为2.6秒及3.3秒；卡片各域、首屏十行及全范围汇总逐项一致。重复切回在短期缓存窗口内复用，显式刷新、身份、批次和分仓相互隔离。数据随后台负载变化，不承诺固定延迟。

本轮还交付此前已验证的基地缺货快照一致性、分仓数据日期、列宽拖动、订单勾选明细导出及DMS独立确认轮次编号修复。DMS新确认生成新身份，同一轮重试保持身份；真实下单仍受DMS客户对接人关系约束，不声称已生成真实订单。

验证：40项定向测试、9项浏览器测试、45项质量测试、233项分仓SQL回归通过；官方类型检查、受影响业务模块严格类型检查与所有者构建通过。主线订单工作台修复已保留，无能力删除、权限调整或已确认历史修复回退。

发布检查补充：完整浏览器回归发现部分嵌入页面没有randomUUID接口，新确认轮次因此无法打开。编号改用Web Crypto安全随机字节生成UUID，保持新轮次独立、同轮重试稳定；两项原始失败的草稿/分仓隔离Excel测试、12项DMS与身份测试、质量快检全部通过。没有采用时间戳或Math.random替代。
