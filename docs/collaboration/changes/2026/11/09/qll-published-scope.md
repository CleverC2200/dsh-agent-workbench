# 全链库存客户端取数一致性

页面查询时点晚于已完成汇总批次时，卡片读取汇总成功，但品类列表把订单和动销窗口推进至页面日期，失去汇总覆盖，回退联查原始订单等资源并被网关在 AUTHORIZE 阶段拒绝。当前账号真实读取复现该路径，不能从通用 DATA_PERMISSION_DENIED 推断某一物理字段缺权。

同月且所选时点不早于已授权完整批次时，公司库存卡片、品类及组织列表按该批次的业务时点绑定动销窗口；库存快照日期独立保留。早于批次的历史查询和其他月份不使用未来批次；渠道继续采用独立时点。元数据拒绝保留错误，不重试原始资源，也不影响可独立读取的渠道数据。现有网关、字段返回检查及基地范围权限不变。

基地品类下钻的默认目标版本原固定为滚动，改为复用既有已发布目标月份/版本选择规则。真实账号当前可用默认版本为月初；不修改目标数量公式、重复冲突处理或有效零值。库存零值保留为0，缺失目标、零动销分母及权限失败保持未知，不估算补齐。

用户要求不新增日期显示或同步说明，已撤回临时日期提示，页面原有布局不变。同步任务及数据库写入不在本次交付范围。

验证：110项定向回归、2项浏览器交互、局部构建及增量lint/format通过。真实网关联调覆盖汇总、品类、华南/郑州和SKU下钻；当前完整批次基地/分仓品类合计与卡片分别一致，差额为0。当前账号真实响应在实际工作台组件中回放，列表恢复且无权限错误、无新增日期提示。正式客户端窗口已观察到原症状；本票未替换正式安装、未推送或发布。


## 独立工作台口径统一

基地周转按所选日期选择需求版本，以库存、目标及计划日均均有效的同批 SKU 计算库存合计／计划日均合计；分仓回顾周转以非负可用库存／正向发货日均计算。公司周转合并两层有效分子、分母，不平均天数。基地与分仓满足率分别沿用各自工作台的已发货客户订单池及截止范围，按分子、分母重新计算公司比率。

卡片、品类列表和组织下钻共用上述范围；基地组织库存和货龄改用独立基地工作台相同的既有汇总类型，分仓组织下钻不再混入基地批次。真实零值、缺失、权限拒绝、分页和筛选约束保留。目标版本按用户所选日解析，不受较早库存批次日改变。周转显示统一两位小数。

本轮新增55项定向页面／逻辑检查、89项SQL检查及实际工作台组件的授权响应回放通过，库存、周转、满足率和组织／品类汇总均完成逐项对账。旧数据源分页测试明确使用“没有完成汇总批次”的响应，继续保留分页与零值断言。发布仍以主线合并、归档、频道与读回回执为准。
