# 单笔审批失败与再次提交

单笔顶部通过的直接提交分支在失败后关闭组件，并用通用提示覆盖服务端原因。同一提交对象发生明确失败后，再调用 submit 会直接返回已缓存错误，不调用接口。

修复保留单笔失败结果并展示服务端业务原因，隐藏追踪编号。明确失败后的人工提交创建新请求；未知结果仍沿原幂等键核对，连续点击只发一次请求。草稿失效或读取失败时显示具体拦截原因。

- 影响版本：Workbench 0.1.98 及此前同一实现；引入提交未确认。
- 修复提交：eaf2b15a、59c4609c。脱敏 fixture 中恢复旧 hook 后，两次提交只有一次调用；修复后是两次，且显示第二次响应。
- 89 项回归通过；补充第二次响应断言后，8 项提交场景复验通过。类型、lint 和格式检查通过。
- 用户反馈重新勾选后点顶部通过仍显示旧报错且无新日志。该入口在本地旧版也可调用两次，现场具体拦截点尚未完全确认，不能将缓存缺陷等同于现场唯一原因。
- 历史覆盖偏重批量与详情弹窗，没有覆盖单笔直接提交及同一弹窗的再次提交。已有回归保留。
- 计划修复版本 0.1.99，发布后由用户重新勾选验收。没有再次执行真实审批、DMS 写入或修改产品主数据。
- 未删除文件或业务能力。权限、当前版本核验、成功回执和未知结果的原意图核对保留。
