# 产销协同来源提示修复

截图中的红色异常来自两处问题：配置中尚无等价来源的分区返回 `SOURCE_NOT_AVAILABLE` 后，被适配器归为查询失败；界面又同时输出错误汇总和同一分区的错误列表，造成重复。

来源缺口及所选期间无快照改为 `unavailable`，保留结构化原因及页面、Agent 上下文。只有实际权限、网关、传输等查询错误进入异常提示；提示中的每个失败来源只显示一次。计算继续保留缺数按零策略，未接来源及失败查询不冒充成功的零值。

2026-10-21 复核发现，原“10月客户计划编码为空”提示已经过时：`agents_sales_plan_demand_m` 当月89777行，其中83307行客户编码非空。已改为当前仍需解决的计划与交货同粒度、同期间及计量单位口径。此修复不把客户月计划与累计交货直接拼接成执行率。

`agents_scm_warehouse_transfer_plan_data_d` 仍为2375行，`plan_month`、`snapshot_date`、`plan_version`、`plan_source`、`plan_qty_unit`、`warehouse_month_transfer_plan` 均未回灌；不能按当前选定月份套用这些计划。其余当前订单阶段、分仓预算归属、批次货龄缺口仍保留在来源上下文和缺失字段文档中。

回归覆盖两个实际 HTML 页面场景：已接查询均成功时不出现红色读取异常；模拟库存返回权限拒绝时仍出现异常且不重复。另复用 APS 受控查询、分区隔离与计算测试。
