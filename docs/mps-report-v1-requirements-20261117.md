## 1. 范围与术语

| 术语 | 含义 |
|---|---|
| 评估当月 | 当前评估版本选择的月份；后续月份相对于该月确定。 |
| 产品范围 | 产品清单中的基地与SKU组合。 |
| 替换品 | 为当前SKU提供历史折算依据的关联SKU；关联本身不决定是否属于产品范围。 |
| 原始值 | 来源或人工修正提供的值，保留其缺失、冲突、失败、负数及真实零状态。 |
| 计算用值 | 本需求明确允许补0或负数归零后供后续计算使用的值；可以与原始值不同。 |
| 目标期末库存 | 按目标周转天数等政策确定的库存目标。 |
| 预测期末库存 | 按库存、生产入库、调拨及发货收支预测的月末结存。 |
| 完整历史月 | 评估当月之前已结束的自然月；当月未结束时不计为完整历史月。 |

本轮覆盖产品范围及异常、无发货处理、周转天数、下市品、负库存、产能层级、需求上传下载及历史发货。公历／农历切换、大类需求另一套计算及其版本管理暂缓，不进入本轮实施。

## 2. 产品范围与池外异常

1. 以产品清单中的“基地＋SKU”为正常计算范围，同一组合不重复计量。
2. 仅作为替换关系引用、未列入该基地产品清单的老SKU，只用于历史折算，不作为池外异常项。
3. 某SKU本身也在该基地产品清单中时，正常参与计算；不能仅因被其他SKU引用为替换品就将其排除。
4. 其他池外记录按以下类别输出异常报告：历史有发货SKU、销售提报SKU、其他。其他类必须带原因说明。
5. 同一基地SKU同时出现在历史发货与销售提报来源中时，两类报告均保留其记录和来源；总异常清单按基地SKU去重并保留全部来源标识。
6. 异常报告与需求计算分别判断。属于正常计算范围且依据有效的需求继续计算，不因出现在异常报告中就自动排除。池外记录不因报告分类而自动加入产品范围。

## 3. 本月无发货依据的成品

当SAP发货数量、已备未备数量、近30天发货均已成功读取，并确认三项均无业务数量时，本月预估发货为0。

此规则不将缺字段、缺记录或读取失败直接认定为真实零；相关输入仍待补，并保留原因。第6节历史发货补0和第5节下市品日均缺失补0属于指定用途的例外，不扩大为所有来源的通用规则。

本月预估发货为0后，预测期末库存仍计入后续生产、入库、调入及调出计划。只有没有后续库存变动时，期末库存才等于当前库存。

库存收支沿用同一时间截点，已发生量与未来计划量分别承接，避免重复计入生产、入库或发货。第7节负库存归零规则同时适用。

## 4. 最终周转天数与库存目标

| 情况 | 目标期末库存处理 | 报告要求 |
|---|---|---|
| 最终周转天数有效且为0 | 目标期末库存为0 | 输出原因和报告，包含有效零值的来源与计算依据。 |
| 最终周转天数为空，查因后仍无有效值 | 保留待补，允许人工补充周转天数 | 输出缺失、冲突或读取失败等可定位的原因；无法定位时明确原因待核。 |
| 补入有效周转天数 | 按有效值重新计算受影响结果 | 保留人工补充及来源信息，刷新对应报告。 |

周转天数为0不强制预测期末库存为0。预测结存继续按库存收支计算。

## 5. 下市品

### 5.1 需求与既有计划

1. 从评估当月起，停止为下市品自动生成新增需求和补货生产计划，仅保留发货及库存滚动计算。
2. 已有生产入库、在途入库、调入及调出仍计入库存收支，停止新增补货不等于抹去已有变动。
3. 下市品已有人工正需求属于人工决策例外：输出异常，保留原值、修正历史及当前有效状态，继续按该有效状态参与现有需求及后续计算。
4. 系统不自动停用、归档或清零已有人工需求；是否停止生效由人判断。异常报告与其决策结果分开保留。

### 5.2 后续月份发货和库存

1. 日均发货直接采用 `ai_db.agents_scm_stock_detail_d.avg_30d_send`，即截止日记录的近30天日均发货，不另行以发货天数或本月预测量重算。
2. 该日均字段为空、记录缺失或读取失败时，计算用值按0处理，并输出缺失或来源异常。真实零与缺失补零在报告中可区分。
3. 后续月份预计发货量按“日均发货量×该月自然天数”计算，并以该月可用库存为上限。
4. 可用库存包含按第5.1节承接的有效库存变动；库存耗尽后预计发货不再继续扣减，期末库存为0。
5. 各期期末库存承接为下一期期初库存。日均发货补0不代表其他缺失库存输入也可补0。

## 6. 历史发货展示、分类和补0

### 6.1 展示与计算口径

1. 第三步加工后需求及其下载补齐上一完整财年的历史发货，按同基地当前SKU自身历史，加替换品历史乘替换系数计算。
2. 物料组、大类、基地和全国按对应明细汇总，筛选与下载采用同一范围和口径。
3. 历史发货缺失、冲突或读取失败时，保留原始状态与原因，按本节规则分类后将相应缺失历史数量补0，补0后的数量同时用于展示、下载和计算。
4. 保留能独立确认的有效历史数量，不因一个缺失项将其他已知数量一并清零。真实零与补零可追溯区分。
5. 补0并不使无效占比变成有效占比。仍无法形成有效占比或其他必要依据时，相关结果保留待补，不将0÷0当成0，不自动均摊需求，也不直接把需求设为0。

### 6.2 先分类，再补0

| 类别 | 判定与输出 |
|---|---|
| 疑似新品或重新上市 | 连续12个完整历史月无实际发货，报告为“疑似新品或重新上市”，同时展示近24个月历史供核对；仅凭无发货不能直接认定具体产品身份。 |
| 短期断档数据异常 | 最近连续1—2个完整历史月无发货，此前有发货，输出短期断档异常及相关月份历史。 |
| 来源异常或其他历史异常 | 读取失败、历史读取不完整、冲突及不符合前两类的异常，输出实际原因和可用依据。 |

1. 分类依据原始、可确认的历史及读取状态。两类无发货情形都按已确认规则补0，并分别输出异常报告。
2. 读取不完整或失败不能凭补出的0判为疑似新品、重新上市或短期断档，应单列来源异常；计算所需缺失历史数量仍按本节约定补0并保留状态。
3. 对正常计算范围内、仍有足够有效依据的记录继续计算需求。报告异常本身不构成停止计算的指令。
4. 历史数量补0不修改原始历史记录，不自动补造缺失的同比、环比、占比或替换关系依据。

## 7. 负库存

1. 期初库存、预测期末库存为负数时，一律将计算用值归0，后续月份承接归零后的库存。
2. 异常报告保留原始负值、所在基地SKU月份、指标、可定位原因及归零后的计算用值。原因暂不明确时显示待核，不能阻止已确认的归零处理。
3. 按明细处理负值后再汇总，不用其他SKU的正库存抵消负值来隐藏异常。
4. 归零不删除原始库存值、人工修正历史或已形成的供需缺口。报告应能区分库存归零结果与原始不足。

## 8. 产能评估与缺口

### 8.1 保持现有指标和算法

报告原第6项的改名建议不实施，指标名称继续使用“负荷率”。保留现有隧道产能及缺失处理，不借层级扩展更改以下口径：

- 单条隧道月产能＝标准日产吨数×有效生产天数。
- 标准日产吨数采用 `ai_db.agents_dim_tunnel_capacity_mi.standard_daily_output_ton`；设备规格吨位不参与日产能换算。
- 物理隧道按基地、生产单位／车间、隧道号去重。多个系列、SKU或产线引用同一物理资源时，汇总产能只计一次。
- 默认每月25天，春节前5天及后5天按日期所属月扣减；人工基地月份生产天数覆盖默认值，生效的生产日数约束和停线约束继续适用。
- 负荷率按内部需求吨数÷隧道月产能吨数计算，ODM不占内部产能。
- 现有缺失或冲突能力的排除、问题记录以及人工资源覆盖规则继续适用，不因本轮补0要求把未知产能视为有效零产能。

### 8.2 补齐查看层级

1. 设备层级支持全国、基地、车间、产线、隧道查看。
2. 在所选设备范围内，支持大类、物料组、SKU的需求及产能占用查看，并使用现有有效的资源关联。
3. 设备汇总与产品汇总保持一致；共享隧道不能按每个SKU或大类重复累加为基地、全国总产能。
4. 没有有效关联的需求保留问题及来源，不能虚构设备归属或产能。

## 9. 第三步需求上传下载

1. 复用现有下载能力，支持当前查看范围的需求及第6节历史发货口径，不删除原有有效需求和审计信息。
2. 上传用于批量维护“基地＋SKU＋月份”的需求修正，字段包括基地、SKU、月份、修正数量、调整原因及必要说明。
3. 上传沿用已确认的明细修正规则：上层自动汇总，兄弟SKU及其他基地不被重摊或挤占，保留系统原值、修正历史、撤销和评估版本隔离。
4. 调整原因沿用销售变化、促销活动、库存调整、供应变化、数据纠错、其他；其他需补充说明。
5. 上传经校验和用户确认后生效。不通过该入口覆盖系统测算依据或原始历史发货；异常数据不能静默覆盖现有有效修正。
6. 下市品的上传修正仍受第5.1节人工需求例外及异常报告约定约束，系统不自动停用该修正。

## 10. 异常报告与处理优先级

报告至少覆盖：三类池外异常、发货输入待补、周转天数缺失或有效零、下市品日均缺失、下市品人工正需求、负库存、历史无发货分类及历史来源异常。现有产能异常报告继续保留。

报告按适用情况包含基地、SKU、月份或历史窗口、异常类别、原始值或原始状态、计算用值、实际处理、来源及原因。未能定位的原因明确待核，不编造原因。页面可查看，完整明细可下载；真实零、补零、归零和人工有效修正可区分。

| 输入或指标 | 处理 | 报告 |
|---|---|---|
| 普通本月发货依据缺字段、缺记录、读取失败 | 保留待补，不能凭缺失触发“三项均无数量” | 保留输入问题。 |
| 下市品后续日均发货缺失或读取失败 | 计算用日均为0 | 保留原始状态和原因。 |
| 历史发货缺失、冲突、读取失败 | 按第6节先分类，再对缺失数量补0 | 分类报告或来源异常，不凭补零分类。 |
| 最终周转天数为空 | 目标库存待补，允许人工补充 | 原因报告。 |
| 最终周转天数有效为0 | 目标库存为0，预测库存仍按收支计算 | 零值来源及原因报告。 |
| 负期初、负预测期末库存 | 计算用值归0 | 原始负值、原因及处理记录。 |
| 下市品已有人工正需求 | 保持当前有效状态计算，由人决定是否停用 | 单列下市品人工需求异常。 |
| 产能缺失或冲突 | 保持现有处理 | 保持现有问题记录。 |

补零或归零只改变本文件授权的计算用值。来源读取失败仍表现为失败并输出原因，不因产生计算用0而显示为读取成功。异常报告本身不自动停用需求。

## 10.1 评估月份与版本

可新建评估的月份为业务实际本月及后两个月，按自然月顺延。选择后续月份时，新建范围仍以实际当前月为准。页头月份下拉可打开已有评估版本的月份。选定月份后，版本下拉只列该月的版本。

选择后，版本关联、评估期间、取数和计算结果必须对应所选月份；不复用其他月份结果。已有版本、历史和草稿保留，不删除或静默迁移。
