# 分仓加载优化与库存修复整合

本轮整合分仓/全链 ASN 订单取数、身份切换及会话返回恢复，以及已批准的重复目标、批次冲销和全链洞察接线修复。保留 GEA 的资源、字段和行范围授权；未授权的数据继续显示未知。

分仓首屏使用同一页面共享的最多两路查询队列，先加载库存与履约；库存日期与数量共读，订单卡片复用同口径缺货 SKU 数，移除卡片未使用的商品属性关联。列表默认全部、10条，筛选与翻页继续走服务端，正常数据按原身份隔离缓存20分钟。

在同一正式 GEA 账号、相同范围下交替运行三轮。串行整屏耗时为30.4/26.9/29.1秒，两路并发为16.4/15.3/15.3秒，中位数下降47%；库存先于其它区块显示。六次业务结果深度比较一致。首屏列表仍需约12秒完成服务端计算，不能将此验收解释为所有网络、账号均达到固定时延。

数据库诊断发现库存批次表保留大量历史快照，而当前查询只使用最新快照；日期不在现有排序键内，且无二级索引。已按本轮授权新增 month_date 的倒排索引 idx_inventory_snapshot_date，并发起历史索引构建。上述47%是索引构建前的查询调度收益；索引完成状态和额外收益另行核验，不提前承诺。未改变业务数据、缺货公式或全局订单时间分配顺序。

删除/旧修复核对：按已确认业务范围移除分仓对经销商订单表的依赖、日期筛选和默认有业务筛选；保留全部/分仓范围、未知值、跨仓FIFO、提交分页和授权失败语义。全链分仓订单同步使用ASN。仅原样整合另一对话已批准的全链洞察规则，未另行改写其它Agent提示词。

验证：182项分仓SQL回归、6项全链ASN回归、36项查询/权限/缓存回归、24项浏览器回归，以及相关构建。其它缺失的目标、计划或订单关联数据不填零。正式DMS当前账号无权限，仅验证接口可达与拒绝处理，不声称正式下单成功。本轮不做三插件联合启动检查。

发布以本轮 PR、CI、固定构建及频道回读为准；本记录不表示已经发布或安装。

## 全链与基地追加优化

全链库存快读改为基地、分仓独立最新快照过滤，卡片与品类目录复用同一快照查询；周转卡片只读取所需动销聚合，避免额外计算补货计划。保留各自仓库范围、数量及空值规则。日期切换仍重新读取对应范围，渠道数据不混入公司库存。

正式受控通道本轮基线整组约40秒且库存查询30秒超时；修改后一次完整读取约25秒，库存约5.3秒返回。品类汇总仍约10.6秒，整体受服务端聚合及并发负载影响；一次与其它探测重叠的运行仍有超时，不能承诺固定响应时间。

基地增加首批查询优先级和单基地当前订单范围下推。全基地首批库存约9.5秒降至5.7秒，整组约13.7秒降至11.7秒；单基地整组约11.4秒。相邻测量库存、货龄、履约结果一致，当前订单随源表更新有变化，不将不同时间的订单结果作为同快照对账。各来源失败独立显示提示，已返回数据保留；目标与辅助指标的真实缺失不补零。

货龄按同仓库、SKU、生产日期、快照先合并有符号库存，再按净正批次计算加权货龄与分桶。正式同一快照的基地60天以上卡片和明细合计一致；未知WMS筛选条件不作等价宣称，不按截图倒推阈值或单位。数量保持件。

回归保留跨仓FIFO、权限失败、最新日期、十条分页、渠道切换和提示词不变的约束。查询警告测试改为验证可见部分数据提示与诊断内容，不依赖页面内部警告组件数量；日期提交测试验证实际使用的共享快照查询。未删除用户能力，未修改提示词或Skill。本轮不做三插件联合启动检查，取数实测不等于本地客户端安装验收。
