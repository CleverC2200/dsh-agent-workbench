# 有效需求与期初库存缺项排查

本轮修复了评估前未准备发货库存输入的问题。原授权开发客户端已重新启动，并在原profile、原5个评估版本上完成真实复验。当前结果仍为部分结果，完整排产业务验收未通过。

## 原因与处理

原输入的12,783行SKU需求和期初库存均未知。单SKU缩小到12行仍能复现。年度、提报和历史系数并非全空，关键缺口是第二步快照状态为 `unread`。第六步只读取关系、件吨和年度数据，第二步的业务输入必须手动点击同步，因此直接进入评估或恢复页面时会漏读。手动同步同一截止日后，源端返回3,598条记录，形成3,522条有效预估和结存，其中3,037条匹配本版首月需求域。

现在业务版本进入需求、加工、约束、评估或报告时会自动准备发货库存；已读取的同版本、同截止日来源复用。正在读取时暂不执行评估。无可用日期或读取失败会发布失败状态并保留原因，不会永久显示准备中，也不把未读当作源表缺数。本地CSV来源和人工发货、剩余入库调整保留。

大类需求页面与问题CSV复用同一份缺项说明，区分本月预估缺失、对应月份销售提报缺失、历史系数缺失及后月递推依赖。期初库存问题说明区分未读/失败、没有同基地SKU记录，以及已读行缺哪些输入或无法估算发运天数。
