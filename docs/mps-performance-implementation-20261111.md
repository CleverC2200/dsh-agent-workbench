# MPS性能优化实施与验收

已完成本地实现、串行整合和真实开发窗口验收。集成分支为 `codex/mps-performance-20261111`，涉及 Workbench 与 Manage。GEA、后端限制、公式和数据权限保持原合同；未推送、合并远端主线或发布客户端。

## 改动与收益

| 环节 | 原行为 | 本轮结果 |
|---|---|---|
| 纯计算 | 每计划行扫描全部件吨、全部调拨边 | 按基地/SKU及SKU分别建一次索引。相同实际Native输入的Node回放24.70秒→2.45秒，完整123,971,869字节结果文本一致 |
| 年度传输 | 全部64,826条源记录读到页侧再剔除空SKU | 仍每页200；只传45,326条非空SKU明细，保留全源前后计数、原100,000上限、配置/业务键校验和19,500条剔除数。327→231次请求 |
| 件吨 | 每100编码串行批读 | 每200编码、最多两批并发，共用原MPS四槽。当前1,286编码39→21次，年度额外197编码5→3次；返回记录和顺序一致 |
| 关系 | 执行评估时重复读四组已读来源 | 仅同scope/config的完整ready结果复用。当前路径80→0次；刷新、busy/error、身份/范围变化继续失效 |
| Worker | 已存在Worker，传输约0.4秒 | 两种无损减重实验收益不足，不引入新协议。计算、传入/回传与测量器读回分开记录 |
| 测量工具 | 临时探针参数容易与owner漂移 | `scripts/measure-mps.mjs`读取明确输入与Manage源码，输出固定元数据；查询ID从可信配置取，月份保留合法范围，编码只保留数量/集合指纹，认证内容不输出 |

当前ready关系路径实际评估255次查询，比原同规模首次取数451次少196次；首次打开页面本身的读取另计，不能用这一数值冒充整页请求数。

## 真实验收

原授权profile在固定Core `6156856b3a33ad2d408c2cf8162df1b32371c3d7` 上使用源码反馈，实际加载脚本与编译产物逐字一致，SQL包含43个命名查询。原安装包版本未升级，不作为三包安装或发版验收。最终合入的后续修改只有测量器/测试和合同文档，运行作者源与已装载产物相同。

| 场景 | 结果 |
|---|---|
| 首轮实际评估 | 121.70秒到Worker返回；Worker2.403秒；255次查询、0查询错误、无页面alert |
| 刷新后再评估 | 158.28秒到Worker返回；Worker2.367秒；255次查询、0查询错误、无页面alert |
| 数学结果 | 两轮Native完整结果逐字一致；第一轮实际Worker输入分别送旧算法与新算法，两者完整输出也都与Native一致 |
| 取消及复用 | 再评估开始后离开Workflow，年度请求取消、无新Worker；已有件吨被复用，没有新增件吨请求 |
| 显式刷新 | 重新读取关系产生80次成功查询；旧结果标“输入已变化”并禁止导出，重新评估完成后恢复有效结果 |
| CSV与XLSX | 求解/产销存CSV各12,783行、逐数量字段一致且两文件内容相同；问题清单33,288行、逐源字段/原因/处理动作一致；金额XLSX实际保存完成、10行、表头冻结，ZIP有效 |
| 有效需求负载 | 200SKU/共享资源，600条有效需求受限排产，首月每SKU需求0.5、排产0.25、满足率0.5；资源不超限，Node与实际Chromium Worker完整结果一致 |
| 原数据 | 5个版本保留；版本名、月份、口径、人工调整、文件、产品/年度/提报/预测/发货输入以及发运rows/values/remaining均与原快照一致。只读重取的来源元数据及目标库存来源更新单列，不声称与旧来源快照完全相同 |

源数据仍有缺项，真实快照完整可排行为0/12,783，问题清单保留33,288项。性能验收不等于源数据已补全，没有用0替代未知。原研究冻结快照的问题数30,251与本次真实重读不同，因此只在同一实际输入上比较算法，未把两个不同来源快照当等价输入。

两轮真实等待存在服务侧波动，剩余时间主要是受控取数。没有放宽后端每页200限制，没有通过参数改名、行内打包或删除完整性校验绕过限制；被拒绝的1000页实验保留为失败证据。
