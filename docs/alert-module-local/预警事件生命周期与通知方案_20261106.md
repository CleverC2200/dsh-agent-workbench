# 预警事件生命周期与通知方案

## 范围
检测任务定义指标、范围、频次和通知人；执行记录记录每次检测；预警事件代表一轮异常，首页卡片与预警清单是事件的不同视图。本期不做隐藏、建议采纳或协同任务。

## 生命周期
1. 有效检测首次发现异常时创建事件，记录开始时间，展示卡片并发送首次预警。
2. 事件未关闭时，每次有效检测更新事件与历史，异常时每次发送反馈；数据截止未变化仍记录并明确标识，不伪造业务变化。
3. 有效检测恢复健康时，标记已恢复、待关闭并记录恢复时间，发送恢复通知；卡片保留。若关闭前再次异常，更新同一事件并保留历史。
4. 用户可直接关闭异常或已恢复事件，无须理由；记录关闭时间及操作者，移出首页但保留在清单。关闭后下一次有效检测仍异常，创建新事件并发送首次预警；检测正常则不创建。
5. 失败、数据不完整或无法判定时不更改风险状态、不判定恢复，记录失败。停用检测任务不自动结束事件。

## 记录与趋势
每次有效检测记录执行时间、数据截止、数值、单位、风险状态、执行编号和数据是否更新；趋势按实际检测点展示，数据缺失不补点，统计期间、累计或快照口径需标明。清单支持查看异常中、已恢复待关闭、已关闭及其历史。

## 通知
按任务通知配置，首次异常发送预警，后续每次有效异常检测发送反馈，恢复时发送恢复通知。发送状态及回执留痕，失败或未知不能声称送达，不自动重发不确定结果。用户关闭本身不发消息。消息由既有飞书配置执行，不为测试向用户发送业务消息。

## 一致性与边界
事件按指标、对象、范围、统计周期和规则身份识别；任务与事件各自独立。关闭和检测更新须在同一持久化锁内排序，避免重复事件。新周期独立事件，不把累计值当成单日值。历史存量需兼容，身份及关闭人以宿主提供的可信身份为准，缺失时不得虚构。

## 验收
覆盖首次异常、持续异常及同截止反馈、升级、恢复待关闭、恢复后再异常、异常直接关闭后重建、正常关闭后无新事件、失败不恢复、并发关闭和检测、通知幂等及 UI/真实飞书回执。技术测试、客户端界面与真实消息送达分别记录。
