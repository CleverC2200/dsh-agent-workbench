# 预警事件生命周期与通知方案

## 范围
检测任务定义指标、范围、频次和通知人；执行记录记录每次检测；预警事件代表一轮异常，首页卡片与预警清单是事件的不同视图。本期不做隐藏、建议采纳或协同任务。

## 生命周期
1. 有效检测首次发现异常时创建事件，记录开始时间，展示卡片并发送首次预警。
2. 事件未关闭时，每次有效检测更新事件与历史，异常时每次发送反馈；数据截止未变化仍记录并明确标识，不伪造业务变化。
3. 有效检测恢复健康时，标记已恢复、待关闭并记录恢复时间，发送恢复通知；卡片保留。若关闭前再次异常，更新同一事件并保留历史。
4. 用户可直接关闭异常或已恢复事件，无须理由；记录关闭时间及操作者，移出首页但保留在清单。关闭后下一次有效检测仍异常，创建新事件并发送首次预警；检测正常则不创建。
5. 失败、数据不完整或无法判定时不更改风险状态、不判定恢复，记录失败。停用检测任务不自动结束事件。

## 记录与趋势
每次有效检测记录执行时间、数据截止、数值、单位、风险状态、执行编号和数据是否更新；趋势按实际检测点展示，数据缺失不补点，统计期间、累计或快照口径需标明。清单支持查看异常中、已恢复待关闭、已关闭及其历史。

## 通知
按任务通知配置，首次异常发送预警，后续每次有效异常检测发送反馈，恢复时发送恢复通知。发送状态及回执留痕，失败或未知不能声称送达，不自动重发不确定结果。用户关闭本身不发消息。消息由既有飞书配置执行，不为测试向用户发送业务消息。

## 一致性与边界
事件按检测任务、指标、对象、范围和规则身份识别；统计周期不参与事件唯一标识。所有指标共用此规则：未关闭事件跨日、跨月、跨年均更新原卡片；恢复正常后保持已恢复待关闭，再次异常仍属于原事件；用户关闭后再检测到异常才新建事件。每次观测保留当次统计期间，卡片展示最新期间和值，不把不同月份累计值当成单日值。任务与事件各自独立，关闭和检测更新须在同一持久化锁内排序，避免重复事件。历史存量需兼容，身份及关闭人以宿主提供的可信身份为准，缺失时不得虚构。

## 验收
覆盖首次异常、持续异常及同截止反馈、升级、恢复待关闭、恢复后再异常、异常直接关闭后重建、正常关闭后无新事件、失败不恢复、并发关闭和检测、通知幂等及 UI/真实飞书回执。技术测试、客户端界面与真实消息送达分别记录。

页面支持添加、编辑、停用、筛选和搜索；相同范围与相同账号禁止重复添加。同一人员可负责多个范围，修改关系保留历史。人员无有效飞书账号时显示不可发送原因。

### 4. 检测任务的推送配置

保留通知频次配置，并增加收件人匹配方式。两个配置独立生效。

| 配置项 | 可选内容及说明 |
|---|---|
| 是否通知 | 关闭／开启 |
| 通知方式 | 固定接收人／按负责人清单匹配 |
| 负责人匹配策略 | 仅精确匹配／组合优先、未命中时回退／指定层级合并 |
| 回退或合并层级 | 勾选基地负责人、品类负责人，按业务需要组合 |
| 通知频次 | 沿用已有一次通知或重复通知模式，界面明确异常与恢复各自的发送行为 |
| 匹配预览 | 输入或选择一个业务对象，显示命中人员、规则层级及遗漏原因 |

建议默认采用“组合优先、未命中时回退”，用户保存时确认回退层级。

- 仅精确匹配。组合对象使用基地 × 品类清单；单基地和单品类对象分别使用对应清单。
- 组合优先。组合命中时使用组合人员；未命中时按勾选层级回退。
- 指定层级合并。将用户勾选的组合、基地、品类层级命中人员合并，支持同时通知现场负责人及上级范围负责人。
- 固定接收人。沿用存量配置。既有任务保留原配置，用户编辑后主动切换到定向匹配。

未匹配人员时，保留预警并显示“通知待处理”。设置人可以补充清单并重新预览，再对未发送对象补发。可增加明确配置的兜底接收人；是否需要该选项待原型验收确认。

### 5. 匹配与消息汇总

1. 读取有效检测结果中的稳定基地及品类标识，按检测粒度确定可用匹配层级。
2. 根据检测任务保存的策略解析人员，过滤停用、无账号及未获授权的关系。
3. 记录每个异常对象的匹配层级、名单版本、接收人及未匹配原因。
4. 按租户与稳定飞书账号去重，将同一次执行中属于该人的异常合并为一条消息。
5. 消息只包含该接收人有权接收的对象。正常对象不生成异常消息，查询失败和无法判定按检测失败留痕。
6. 每条对象明细保留预警事件 ID，消息汇总后仍能回溯各自事件与发送结果。

清单未覆盖某对象时，可以继续发送其他已匹配对象；执行记录同时展示检测结果和通知覆盖情况。例如“检测成功，4 项异常，3 项已匹配，1 项通知待处理”。

对象维度缺失时显示“缺少匹配字段”。同名不同编码按业务标识区分，账号同名按稳定人员标识区分。

### 7. 持续异常、恢复与清单变更

事件唯一标识、跨月持续、恢复待关闭及关闭后新一轮的规则沿用既有设计。

通知去重使用事件、接收人、消息类型及对应执行标识。一次通知模式按事件与接收人记录首次发送；重复通知模式按执行记录去重。一次执行的发送重试保持同一业务标识。

清单变更后，新执行使用最新有效关系。建议新接手人员收到一次当前异常交接通知，原接收人在失去授权后停止接收后续内容。一次通知模式下的新增接收人也按接收人维度判断是否已通知。

恢复消息面向实际收到过该事件异常且当前仍获授权的人员，记录恢复通知依据。首次通知未送达、恢复时已无授权等情形单独留痕。一次通知模式是否包含恢复消息需在界面写明，并与既有实际实现核对后统一。

本次将人员变更交接、恢复接收人及通知频次交互作为验收确认项。

### 8. 发送可靠性与授权

检测结果先持久化，再生成通知队列。业务检测成功与消息送达分别记录；发送失败展示错误及重试入口，未知结果先核对回执，避免重复发送。

发送记录保存名单版本、收件人快照、对象明细、幂等标识、请求时间和回执状态。同一执行并发触发时按持久化唯一约束阻止重复入队。

原有按设置人隔离继续用于检测任务、预警管理及完整执行上下文。新功能需增加接收人对消息中异常摘要的授权校验。

接收消息后的详情访问有两种可落地方式，建议一期提供有限摘要详情。服务端按租户、当前人员及关联事件授权校验，仅展示收件人所负责的对象。检测配置与完整 AI 上下文仍由设置人查看。负责人被移除时更新后续访问授权。

### 10. 验收标准

| 场景 | 预期结果 |
|---|---|
| 一个检测任务出现多个对象异常 | 各对象匹配自己的负责人 |
| 组合命中 | 组合优先策略只使用该组合人员 |
| 回退开启或关闭 | 严格按保存策略解析并展示依据 |
| 指定层级合并 | 合并选定层级人员，同账号去重 |

| 负责人缺失、停用、账号无效、维度缺失 | 明确原因，其他有效对象继续发送 |
| 清单修改 | 新执行使用新版本，历史可追溯 |
| 持续异常或跨月检测 | 原事件延续，按配置频次通知 |

### 11. 同一接收人多条预警合并发送（本次明确要求）

同一人员需要接收多条预警时，系统先按人员汇总，再发送合并消息。每条异常明细保留对应的预警事件、检测任务及匹配依据。

**合并范围**

- 同一次检测产生的多条异常，按租户及稳定飞书账号标识合并；同一人员因多个负责人关系重复命中时只保留一次。
- 多个检测任务在同一发送窗口内产生的消息，也按同一接收人合并。建议采用可配置的短合并窗口，初始建议为 60 秒，自第一条待发消息入队起计时，后续消息不延长截止时间；窗口值待验收确认。
- 不同接收人、不同租户分别汇总。发送前逐条检查对象授权及任务通知策略，只合并本次允许发送的明细。
- 窗口内同一事件多次更新时，展示截至窗口截止时的最新有效状态，并记录本窗口检测次数。若窗口内先异常后恢复，标明“本窗口曾异常，现已恢复”，保留状态变化说明。
- 首次异常、持续异常、升级和恢复可出现在同一消息中，按状态分组展示，每条保留自身业务时间与数据截止。

**消息展示**

标题示例为“预警汇总｜3 项异常，1 项恢复”。每条明细展示基地、品类、指标、数值、单位、判定依据、异常或恢复状态及数据截止。不同指标和单位逐条展示，不做数量相加。消息提供具有对象权限校验的详情入口。

示例：张负责人同时负责“遂平基地 × 水饺”和“遂平基地 × 汤圆”，同一窗口又收到另一检测任务的水饺库存异常，则收到一条包含三条业务明细的汇总消息。相同事件的重复入队先去重，再参与汇总。

**发送、重试及长度限制**

- 每个汇总批次保存租户、接收人、窗口起止、明细列表、发送状态及飞书回执；明细关联原始事件和执行记录。
- 窗口截止后冻结批次，后续新增消息进入下一批。发送成功后，将该回执关联到批次内每条明细。
- 失败重试沿用原批次及幂等标识。回执未知时先核对结果，避免将同一批次重新合并后重复发送。
- 单条消息超过飞书实际消息类型长度上限时，按可容纳明细数拆成带序号的汇总消息；每个分片独立记录状态，仅重试失败分片。具体长度限制在接口联调中核对。
- 执行记录同时展示“产生多少条预警明细、覆盖多少人、实际发送多少条汇总消息”，并能展开查看个人消息内容及明细回执。
- 合并能力作为新增待开发要求；当前原型已演示单次执行按人汇总，跨检测任务合并窗口及失败重试交互待补齐。

**补充验收**

| 场景 | 预期结果 |
|---|---|
| 同一任务三个异常均匹配同一人 | 一条汇总消息，包含三个异常对象 |
| 同一人被基地、品类及组合关系重复命中 | 同一事件只出现一次 |
| 不同检测任务在合并窗口内发给同一人 | 一条汇总消息，明细保留各自来源任务 |
| 两个人分别负责不同对象 | 各自收到其授权对象的汇总 |
| 同一事件窗口内重复更新或恢复 | 展示最新状态和变化说明，历史检测可追溯 |
| 窗口到期后继续产生消息 | 原批次按时发送，新消息进入下一批 |
| 消息过长或部分分片失败 | 按序号拆分，成功分片不重复发送 |
| 单次通知模式、已发送记录、重试并发 | 先按通知策略及幂等规则筛选，合并不增加重复通知 |
