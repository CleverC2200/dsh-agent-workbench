# 分仓库存页面来源

当前订单与缺货采用分仓下游客户有效未完成客户订单；满足率采用当月已发货客户订单池。ASN用于向基地补货和待收明细；当前调拨备单与在途按分仓总量表字段统计。整合及验证边界见 [2026-10-30 记录](../../docs/collaboration/changes/2026-10-30-inventory-integration.md)。

从隔离资源库 `dsh-agent-fc-plugin` 的固定提交 `906b3b08947b71cecf627073c0b0e9a389b692bf` 迁入。交付 HTML 版本为 `0.2.6-preview.9`；旧源码快照标记 `preview.7`，因此验收分别对照该提交的已交付 HTML 与源码，不能仅凭版本字符串判断等价。

只保留构建所需源码和原有定向测试，未引入旧 node_modules 软链、旧发行脚本或其它业务入口。`scripts/build-inventory-fc.mjs` 是工作台侧构建入口。Agent Skill 与会话提示词由同级 Agent Manage 提供；看板专用 AI 洞察提示词由本页面单独维护。

输出 `build-inputs.json` 记录参与页面构建的源码 SHA256。旧页面仍在原资源仓保留，本目录没有覆盖或删除旧入口。

分仓本月订单计数、准确率基地字段与仍不能计算的字段，见[2026-10-20来源复核](../../docs/fc-accuracy-source-recheck-20261020.md)。当前待发与本月履约分别说明，业务配置不计入同步缺失指标。

四个Agent新增日期发货、有值库存范围与独立仓库筛选的来源及验证，见[2026-10-20数据补充](../../docs/four-agents-data-refresh-20261020.md)。当前本地构建与正式只读取数对账不代表客户端已经安装。

同步数据的剩余字段统一维护在[缺失字段清单](../../docs/agent-missing-fields.md)，页面仅保留数值范围与必要查询错误。布局继续沿用本页原始样式，指标卡按业务窗口宽度换行，宽表格在表格区域滚动。

看板「AI 洞察」使用 [分仓规则包 V1.0 的提示词](insight-prompt.md)，经绑定页面的分仓 Consumer 调用 GEA 模型，原分仓 Agent Skill 不变。输入复用全范围汇总，不采纳当前页排名；订单扣减后的可供量与目标库存按同一可比 SKU 范围计算差额和偏差率，保留缺失目标计数。60/90 天汇总不能替代规则中的91天及以上库存，缺失字段明确为空。结果缓存20分钟，模型等待或失败不阻塞卡片和列表；不合格式最多重写一次，仍失败不缓存。

分仓总览在全部/单仓范围均使用带显式分仓参数的轻量库存与货龄汇总，共用快照日期后独立取数；不再先等待全分仓聚合。单仓筛选在批次计算和货龄列表动销聚合前执行。卡片继续使用可加和的批次数量与货龄乘积，不从最大货龄或SKU平均值反推；货龄失败保留已完成的库存。

同一快照、仓库、SKU、生产日期及原查询业务范围内，先汇总有符号批次数量，再以净正批次计算货龄、分段和风险。完全冲销批次不再贡献旧货龄；不能用其它 SKU、仓库或生产日期抵消。`negative_qty` 表示汇总后仍为负的批次余额，库存总量继续保留有符号净额。原始明细不作改写。

重新生成库存 SQL 后，使用 `scripts/net-inventory-batches.py` 对交付配置应用同批次净额步骤；执行 `scripts/test_batch_net_balances.py` 和 `scripts/test_batch_age_lists.py` 核对冲销、货龄、风险及分页。SQL 配置仍是页面读取和打包的唯一查询来源。

同月、版本、基地和 SKU 的目标记录逐字段核一致性：全非空且唯一值取一次，不对重复目标求和；冲突或空值混合保持未知。初始/管理/最终目标作为同一优先级决策校验，冲突不得借空值回退到另一目标；日均计划仅全量缺失时按本版本既有计划公式补算，冲突不得回退。聚合输入在内部派生表只计算一次，再判断一致性；缺失和真实 0 分开。重新生成查询后执行 `scripts/normalize-target-consensus.py`，回归见 `scripts/test_base_target_versions.py`。

### 补货数据一致性（2026-11-03）

补货卡片、列表、建议与确认清单及其库存日期入口要求读取已校验汇总批次（`summaryRoute.required`）。批次未就绪或不覆盖请求的时间范围时返回结构化不可用状态，不自动替换为实时明细；正常记录继续计入，异常记录沿原规则单独处理。

页面按北京时间自然日、身份、配置与显式刷新代次共用汇总批次。元数据不会因原 20 分钟缓存到期而让后打开的列表切换到另一批次；首屏响应的短缓存到期后，仍用已选择的批次重读。刷新或跨日可以重新选批次，新数据允许改变数值。每个读取器固定自己的刷新代次，避免刷新中的旧请求跨入新一轮读取。不同身份不共享业务数据；相同权限、汇总批次和计算输入应得到相同结果。用户导入的计划、补货周期规则属于计算输入。

此变更不新增表、不修改补货公式或每日同步 SQL。首次未就绪后可用页面刷新重新读取；不通过无限重试绕过字段或资源权限。

### 当前库存、调拨与客户执行单来源（2026-11-10）

用户确认以重新同步后的最新来源为准。新总量与旧批次明细数量不一致时，当前库存和调拨指标采用新总量，不用旧数量回填；新来源的真实零保留为零，字段缺失保持未知。货龄仍按最新可用的批次明细计算，不按库存总量差额缩放或分摊。新总量表没有同步时间字段，此处“最新”指上游串行同步完成后的当前表内容，不能推断逐行更新时间。

当前现存、可用、占用、冻结数量分别取 `agents_scm_warehouse_total_data_d` 的 `live_qty`、`available_qty`、`pack_unit_qty`、`freeze_qty`；调拨中、备单、在途分别取 `warehouse_transfer_qty`、`transfer_prepare_qty`、`transfer_onway_qty`，单位均为件。按 `warehouseid + material_code` 唯一关联，重复键不放大数量。该表没有业务日期，不虚构历史快照。

当前下游客户订单的需求、占单、发货分别取 `agents_dwd_scm_execute_detail_mi` 的 `adjust_order_qty`、`pack_unitqty`、`delivery_qty`，这些字段已经是件，不再次除业务单位换算率。执行行按组织、货主、执行单号与行号核唯一；继续排除关闭、取消、无效和调拨类型订单，异常行不影响正常行。旧执行表只补客户及商品名称，不提供数量。月度满足率仍保留已发货订单池的原公式，执行单到实际发货仓的关联改用新执行表。

仓库范围仍按库存明细的分仓分类和已有权限控制，分仓排除 N436、Y204，基地归属规则不变。月度计划、货龄分段、动销继续来自各自原明细，因为这两张新表不提供对应历史或批次信息。

卡片、列表、确认清单通过现有汇总批次读取。配套 V18 同步 SQL 与本次查询调整必须一起部署；只更新客户端而保留 V17 会继续读到旧汇总。V18 保留先生成候选批次、校验后启用及旧批次保留流程，并新增两张来源的前后指纹与空表、空键及重复键检查，不需要新增表或权限。

生成器为 `scripts/update-fc-warehouse-sources.py`，在其他库存 SQL 生成步骤后执行；业务回归为 `scripts/test_fc_new_warehouse_sources.py`。部署时需同时替换生产调度中的汇总 SQL。

### 货龄结构产品标签（2026-11-05）

“产品标签”按商品编码读取 `agents_dim_material_prod_sales_info_d.tag`，保留原值，空值显示 `-`。先完成原库存筛选、全范围合计和分页，再关联当前页商品的标签；重复一致标签取一次，冲突保持未知，不扩大库存行数。主数据字段仍经 GEA 受控查询及返回权限处理，标签无返回权限时保留其余已授权库存字段。

明细与汇总路径共用此展示口径，不新增汇总表字段，不修改每日同步 SQL。重新生成货龄查询后执行 `scripts/update-fc-aging-product-tag.py`；回归见 `scripts/test_fc_aging_table.py`、`tests/fc-aging-product-tag.test.mjs` 和 `tests/fc-aging-table.browser.mjs`。
