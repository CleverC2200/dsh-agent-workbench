# 分仓库存页面来源

分仓向基地的当前订单采用未收货完成的 ASN，关联基地出库占用；月度履约另用执行侧统计。整合及验证边界见 [2026-10-30 记录](../../docs/collaboration/changes/2026-10-30-inventory-integration.md)。

从隔离资源库 `dsh-agent-fc-plugin` 的固定提交 `906b3b08947b71cecf627073c0b0e9a389b692bf` 迁入。交付 HTML 版本为 `0.2.6-preview.9`；旧源码快照标记 `preview.7`，因此验收分别对照该提交的已交付 HTML 与源码，不能仅凭版本字符串判断等价。

只保留构建所需源码和原有定向测试，未引入旧 node_modules 软链、旧发行脚本或其它业务入口。`scripts/build-inventory-fc.mjs` 是工作台侧构建入口。Agent Skill 与会话提示词由同级 Agent Manage 提供；看板专用 AI 洞察提示词由本页面单独维护。

输出 `build-inputs.json` 记录参与页面构建的源码 SHA256。旧页面仍在原资源仓保留，本目录没有覆盖或删除旧入口。

分仓本月订单计数、准确率基地字段与仍不能计算的字段，见[2026-10-20来源复核](../../docs/fc-accuracy-source-recheck-20261020.md)。当前待发与本月履约分别说明，业务配置不计入同步缺失指标。

四个Agent新增日期发货、有值库存范围与独立仓库筛选的来源及验证，见[2026-10-20数据补充](../../docs/four-agents-data-refresh-20261020.md)。当前本地构建与正式只读取数对账不代表客户端已经安装。

同步数据的剩余字段统一维护在[缺失字段清单](../../docs/agent-missing-fields.md)，页面仅保留数值范围与必要查询错误。布局继续沿用本页原始样式，指标卡按业务窗口宽度换行，宽表格在表格区域滚动。

看板「AI 洞察」使用 [分仓规则包 V1.0 的提示词](insight-prompt.md)，经绑定页面的分仓 Consumer 调用 GEA 模型，原分仓 Agent Skill 不变。输入复用全范围汇总，不采纳当前页排名；订单扣减后的可供量与目标库存按同一可比 SKU 范围计算差额和偏差率，保留缺失目标计数。60/90 天汇总不能替代规则中的91天及以上库存，缺失字段明确为空。结果缓存20分钟，模型等待或失败不阻塞卡片和列表；不合格式最多重写一次，仍失败不缓存。

分仓总览在全部/单仓范围均使用带显式分仓参数的轻量库存与货龄汇总，共用快照日期后独立取数；不再先等待全分仓聚合。单仓筛选在批次计算和货龄列表动销聚合前执行。卡片继续使用可加和的批次数量与货龄乘积，不从最大货龄或SKU平均值反推；货龄失败保留已完成的库存。

同一快照、仓库、SKU、生产日期及原查询业务范围内，先汇总有符号批次数量，再以净正批次计算货龄、分段和风险。完全冲销批次不再贡献旧货龄；不能用其它 SKU、仓库或生产日期抵消。`negative_qty` 表示汇总后仍为负的批次余额，库存总量继续保留有符号净额。原始明细不作改写。

重新生成库存 SQL 后，使用 `scripts/net-inventory-batches.py` 对交付配置应用同批次净额步骤；执行 `scripts/test_batch_net_balances.py` 和 `scripts/test_batch_age_lists.py` 核对冲销、货龄、风险及分页。SQL 配置仍是页面读取和打包的唯一查询来源。

同月、版本、基地和 SKU 的目标记录逐字段核一致性：全非空且唯一值取一次，不对重复目标求和；冲突或空值混合保持未知。初始/管理/最终目标作为同一优先级决策校验，冲突不得借空值回退到另一目标；日均计划仅全量缺失时按本版本既有计划公式补算，冲突不得回退。聚合输入在内部派生表只计算一次，再判断一致性；缺失和真实 0 分开。重新生成查询后执行 `scripts/normalize-target-consensus.py`，回归见 `scripts/test_base_target_versions.py`。
